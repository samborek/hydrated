# Project Rules & Knowledge Base

## Build & Git Policy
- **Pre-push Build Check**: ALWAYS run `yarn turbo run build --filter=@galacticcouncil/main` before pushing to git. This ensures that generated type definitions (like theme tokens) are present and that there are no type errors, preventing Vercel deployment failures.
- **Git Push Strategy**: Push only when explicitly requested or at major milestones. Bundle related changes.

## Build Optimization
- **Storybook Separation**: Storybook builds are slow and moved to a separate `build:storybook` task. Standard builds now only compile the library/app, significantly reducing CI time.
- **Lazy Loading DevTools**: Dev-only tools like `ReactQueryDevtools` and `TanStackRouterDevtools` are lazy-loaded in `__root.tsx` to keep the production bundle size smaller.
- **Turbo Selection**: Use `-filter` flags (e.g., `--filter=@galacticcouncil/main`) to build only what is necessary, leveraging Turbo's cache for unmodified packages.

## Troubleshooting & Handled Issues

### Missing Theme Tokens (Build Error)
- **Issue**: Build fails with `Could not resolve "./dark.json"` or missing JSON files in `packages/ui/src/theme/tokens/`.
- **Cause**: These files are generated by `yarn theme` and are ignored by git. Turbo isolations may prevent them from being available to downstream apps if not defined as outputs.
- **Fix**: 
  1. Run `yarn theme` inside `packages/ui`.
  2. Ensure `turbo.json` includes `"src/theme/tokens/*.json"` in the `outputs` of the `build` task.

### i18n / Translation Type Errors
- **Issue**: `t("key")` calls causing TypeScript errors (e.g., `Argument of type '...' is not assignable to parameter of type '...'`).
- **Fix**: Use `(t as any)("key")` to bypass strict i18n key type checking when necessary, especially in components where the translation keys are dynamically constructed or from different namespaces.

### Component Layout (StatusBar / Pills)
- **Issue**: Feedback and RPC pills having inconsistent gaps or floating incorrectly.
- **Fix**: Group them in a shared `SStatusBar` container with `position: fixed; right: 0; bottom: 0;` and a consistent gap (using shared paddings). Avoid individual `bottomPinned` offsets that rely on manual calculation.

### UI Styling Fixes (Feedback & Select)
- **Dropdown Width**: The `Select` component may not fill 100% width by default. Use a container selector `& > button { width: 100% !important; justify-content: space-between !important; }` to force it to match other form fields.
- **Thumbnail Previews**: For image uploads, use a fixed size (e.g., `60x60`) with `object-fit: cover` to maintain aspect ratio and alignment.
- **Unused Imports**: Styled components may trigger lint errors if `css` or `mq` are imported but not used. Clean these up to keep the build green.
